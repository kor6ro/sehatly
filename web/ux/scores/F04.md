## Alasan per sel (satu fakta; rujukan file bukti)

**Halodoc** (`halodoc.md`): K1 4 — profil offline sudah memuat strip tanggal + slot jam + CTA "Buat Janji"; CTA nonaktif sampai slot dipilih (S1). K2 3 — harga "Rp 450.000 / bayar di rumah sakit", faskes, pengalaman, "Slot Guarantee"; **tanpa rating & tanpa STR/SIP** di profil offline (S1). K3 **N/V** — state error/parsial tidak teramati. K5 **5** — Bahasa, Rupiah, faskes lokal, phone-first. K6 3 — STR/SIP tidak dipublikasikan (minimalisasi); consent tidak teramati. K7 2 — **model kepercayaan terbelah**: offline tanpa rating, online berbintang + ratusan ulasan; badge tanpa kriteria publik (S1/S2). K8 4 — jadwal+s slot memakai endpoint `/jadwal` & `/slot` yang ada; daftar ulasan butuh endpoint baru.

**Alodokter** (`alodokter.md`): K1 4 — satu halaman: rating, bio, faskes+harga, jadwal per faskes, CTA "Buat Janji" (S1/S2). K2 3 — rating "100%" + 163 pasien + jadwal + harga per faskes; kredensial hanya gelar; tidak ada nomor registrasi/registry (S1). K3 4 — state jadwal kosong jujur ("Saat ini belum terdapat jadwal… silakan pilih dokter lainnya") sambil mempertahankan rating (S1). K4 N/V. K5 **5** — Bahasa, Rupiah, RS lokal. K6 2 — **nama lengkap reviewer di JSON-LD** (risiko privasi) + adtech di halaman (S1/S2). K7 3 — rating persentase vs data 5/10; ulasan 2020–2024 + satu isi kosong tetap dihitung. K8 3 — layout dapat dibangun; butuh endpoint ulasan + agregat.

**Practo** (`practo.md`): K1 4 — semua di satu profil + CTA "Pick a time slot" ₹500. K2 **5** — nomor registrasi + konsil + tahun **ditampilkan publik**, badge "Medical Registration Verified", ulasan hanya dari janji terverifikasi, disclaimer tegas, dokter membalas (S1–S4). K3 4 — filter/sort/pagination ulasan + aturan skor minimum (≥10 rekomendasi / ≥5 feedback) (S4). K4 N/V. K5 1 — India, ₹, bahasa Inggris. K6 4 — masking PII reviewer (bintang) + nomor registrasi adalah data profesi publik. K7 3 — persentase dokter vs bintang klinik + ulasan 8–10 tahun + banner upsell. K8 3 — pola dapat dibangun; butuh endpoint ulasan + verifikasi registrasi (data STR ada tetapi belum dipublikasikan).

**Zocdoc** (`zocdoc.md`): K1 3 — profil + "Book an appointment for free" (cache; live 403). K2 **5** — ulasan **closed-loop** ("every review is written by an actual patient"), sub-skor bedside manner/wait time, kredensial (board cert, NPI), transparansi Partner Reviews (S2–S4). K3 3 — aturan pengumpulan 120 hari + moderasi; zero/empty state N/V. K4 N/V. K5 1 — AS. K6 3 — closed-loop kuat, tetapi **provider dapat memilih tidak menampilkan ulasan** dan ambang <30 memicu pengumpulan ulasan non-platform (S4). K7 4 — tab Highlights/About/Insurances/Locations/Reviews/FAQs + sub-skor; terstruktur. K8 2 — butuh rantai booking→konfirmasi→ulasan yang belum ada di Sehatly; insurance tidak relevan.

## Yang TIDAK TERVERIFIKASI (membatasi keyakinan)

1. Aksesibilitas N/V semua kandidat (15% bobot hilang).
2. Zocdoc profil live 403 (hanya cache); Doctolib 403 dan status ulasannya kontradiktif.
3. Apakah nama reviewer dimasking di UI Alodokter (JSON-LD menunjukkan nama lengkap).
4. Praktik UI pasti rating distribution/empty state di kandidat mana pun.
5. Uji pengguna nyata belum dijalankan; benchmark bukan pengganti uji pengguna.

# Skor F05 "Pilih jadwal dan booking" (v0.1)

Tanggal riset: **2026-10-01**. Rubrik: `web/ux/rubric.md`. Bukti per aplikasi: `web/ux/evidence/F05/<app>.md` (setiap alasan mengutip fakta + URL/tanggal di file itu).

## Aturan penerapan

- Kriteria tanpa bukti = **N/V**, dikeluarkan, bobot dinormalisasi ulang.
- **Kriteria 4 (Aksesibilitas) = N/V untuk SEMUA aplikasi**: tidak ada pengukuran kontras/ukuran target sentuh/fokus keyboard yang dilakukan di sesi ini terhadap aplikasi mana pun. Bobot terverifikasi maksimal = **85%** (Zocdoc: 70%, lihat bawah).
- Semua alur kandidat **berhenti di gerbang login/PII** (tidak ada akun dibuat, tidak ada form dikirim) → hitungan "sampai konfirmasi" memakai langkah teramati + langkah terdokumentasi resmi, ditandai per kasus.

## Pemenang dan "best of" per langkah

Syarat pemenang (rubrik): ≥2 sumber bukti independen **dan** ≥70% bobot terverifikasi.

- **Sumber pemenang:** Halodoc memenuhi (situs+FAQ resmi, 2 store listing, 2 berita; 85%). Calendly memenuhi (help/blog resmi, press release, Mobbin, PageFlows; 85%).
- **Doctolib didiskualifikasi sebagai sumber pola** (red flag consent terverifikasi) meski skornya dihitung.
- **Tidak ada pemenang tunggal di semua kriteria:** Halodoc dan Calendly seri di total (3,77), dengan profil berbeda (Halodoc unggul konteks Indonesia + diamati langsung; Calendly unggul efisiensi + kelayakan stack).

**Keputusan: "best of" gabungan** — per langkah:

| Langkah F05 | Pemenang langkah | Sumber + tanggal | Alasan fakta |
|---|---|---|---|
| Ringkasan keputusan sebelum komitmen (biaya, faskes, kebijakan) | **Halodoc** | H1, diakses 2026-10-01 | Biaya + faskes + lencana "Slot Guarantee" + kebijakan batal tampil di profil sebelum tombol booking (diamati); Practo (P6) jadi pembanding (biaya + "no booking fee"). |
| Pilih tanggal digabung dengan slot (satu layar) | **Calendly** | C18/C19, diakses 2026-10-01 | Tanggal + jam di halaman yang sama; menghapus langkah "pilih tanggal → baru muat jam" menjadi satu kontinum (dokumentasi resmi + rekaman pihak ketiga). |
| Grid slot: yang tidak tersedia tetap terlihat + alasan | **Halodoc** (diamati) + koreksi **Practo** (P7) | 2026-10-01 | Halodoc: pita jam per hari dengan CTA nonaktif sampai slot dipilih; Practo: slot terbook "di-abu-abukan", bukan disembunyikan. |
| Gerbang komitmen: CTA nonaktif + alasan inline | **Halodoc** | H1, 2026-10-01 | "Buat Janji" nonaktif + "Pilih slot waktu utk melanjutkan" (diamati). |
| Form detail minimal | **Calendly** | C8, diakses 2026-10-01 | Hanya nama + email wajib; pertanyaan lain opsional → inspirasi meminimalkan field wajib (Sehatly: keluhan & lampiran tetap opsional). |
| Penanganan slot-bentrok saat konfirmasi | **Tidak ada sumber benchmark** | — | Semua kandidat berhenti di gerbang; pola memakai mekanisme Sehatly yang sudah ada (`SlotTakenNotice`, 422 `slot`). |
| Layar sukses + aksi lanjut terlihat | **Calendly** (dengan adaptasi) | C10/C13, diakses 2026-10-01 | Halaman konfirmasi + tautan batal/reschedule; Sehatly hanya punya endpoint batal → tautan reschedule tidak dibangun (lihat pertanyaan terbuka). |

**Tingkat keyakinan keputusan: sedang.** Alasan: bobot terverifikasi 85% untuk semua pemenang langkah (≥70% terpenuhi), ≥2 sumber independen per pemenang, pengamatan langsung untuk Halodoc/Alodokter/Practo; tetapi UI live Calendly, Doctolib, Zocdoc tidak terender/diblokir, semua alur berhenti di gerbang login, dan kriteria aksesibilitas N/V untuk seluruh kandidat.

## Yang TIDAK TERVERIFIKASI (ringkas)

- Seluruh kriteria aksesibilitas (semua kandidat) — tanpa pengukuran.
- UI live Calendly/Doctolib/Zocdoc; layar native semua kandidat; semua langkah setelah login.
- State loading/error/offline untuk Halodoc, Alodokter, Practo; copy state kosong Calendly/Zocdoc.
- Google Calendar appointment scheduling — kandidat dibuang, tidak diverifikasi.
- Jumlah field form booking Practo/Zocdoc live; apakah akun wajib di Zocdoc 2026 (sumber bertentangan).

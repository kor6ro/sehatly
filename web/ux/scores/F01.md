# Skor F01 — Daftar dan login (OTP)

Tanggal riset: **2026-10-02**. Rubrik: `web/ux/rubric.md`. Bukti: `web/ux/evidence/F01/*.md`.
Aturan: hanya nilai yang ada buktinya; tanpa bukti = **N/V** (dikeluarkan, bobot dinormalisasi ulang). Pemenang butuh **≥2 penerbit independen** dan **≥70% bobot terverifikasi**.

**Titik awal hitungan bersama:** (A) belum punya akun → daftar sampai akun terverifikasi; (B) sudah punya akun → login sampai token aktif. Native app tidak dibuka; hitungan dari langkah terdokumentasi resmi (BENCHMARK_PROMPT aturan #4).

## Alasan per sel (satu fakta; rujukan file bukti)

**Mobile JKN** (`mobile-jkn.md`): K1 3 — 5 field registrasi + 1 OTP, login 3–4 input + captcha (S1). K2 4 — biometrik terdokumentasi; lupa sandi 3 kanal; T&C sebelum OTP (S1). K3 3 — pemulihan 3 kanal + wajib login ulang setelah ganti sandi, tetapi state kode salah/kedaluwarsa N/V (S1). K4 N/V. K5 3 — Indonesia, phone-first, tetapi captcha berulang (keluhan pengguna S4). K6 4 — checkbox persetujuan eksplisit pada pendaftaran; biometrik digerbangi password (S1). K7 4 — langkah satu tujuan per layar (S1). K8 3 — OTP+resend bisa dibangun; biometrik butuh native/WebAuthn (tidak ada di stack).

**BCA/myBCA** (`bca-mybca.md`): K1 4 — registrasi 3 kredensial + verifikasi; login 2 field atau 1 aksi biometrik (S1). K2 4 — tujuan OTP utama + cadangan, riwayat kode di menu, aturan biometrik eksplisit (S1/S2). K3 3 — pemulihan pengiriman OTP ada; lockout/kedaluwarsa N/V. K4 N/V. K5 3 — bank Indonesia, Bahasa; keluhan pengguna lockout setelah update (S5). K6 4 — biometrik+PIN+OTP, auto-disable melindungi akun; daftar perangkat tidak terdokumentasi. K7 3 — 12 langkah help, dua prosedur bercampur (S2). K8 3 — pengaturan kirim OTP bisa dibangun; biometrik perangkat tidak.

**Gojek/GoPay** (`gojek-gopay.md`): K1 **5** — login 1 nomor + 1 kode 4 digit, ≈3 ketukan; silent/missed-call 0 field kode (S1). K2 4 — kirim ulang ≥30 dtk + tukar SMS↔WhatsApp; pemulihan ganti nomor 2 kode (S1/S3). K3 3 — batas biometrik 3/2 + passcode; lock PIN 60 menit; state kode kedaluwarsa N/V (S2/S4). K4 N/V. K5 4 — Bahasa, kanal WhatsApp, phone-first (S1–S3). K6 N/V — tidak ada bukti consent/masking/privasi notifikasi. K7 3 — kebijakan satu perangkat memaksa logout perangkat lain (S5). K8 4 — OTP+resend+tukar kanal feasible; Sehatly sudah punya driver WA (`FonnteOtpSender`).

**Bank Jago** (`bank-jago.md`): K1 3 — perangkat baru 6–8 langkah (S2/S3). K2 4 — tinjau nama perangkat + waktu + "This Was Me"; jalur alternatif eksplisit (S2/S3). K3 4 — pemulihan berlapis (perangkat lama → e-KTP+selfie/pertanyaan → CS); CS = manual (S3). K4 N/V. K5 3 — Bahasa/Indonesia; tuntutan e-KTP+selfie tinggi. K6 **5** — Device Access/Manage Devices, 2-step verification perangkat baru, Transaction Authentication (S4). K7 3 — multi-jalur kompleks; 9 entri pengaturan (S4). K8 3 — manajemen perangkat + OTP bisa dibangun; verifikasi wajah butuh vendor.

**WhatsApp** (`whatsapp.md`): K1 **5** — one-tap/zero-tap 0–1 langkah; autofill iOS 26 native (S1–S4). K2 4 — template punya peringatan kedaluwarsa + "jangan bagikan" (S1). K3 4 — forwarding dimatikan, hanya perangkat utama, TTL server-side (S1/S5). K4 N/V. K5 4 — kanal dominan Indonesia; butuh opt-in & WhatsApp Business (S5/S6). K6 4 — E2E, hanya perangkat utama; jangan jadikan nomor identitas (S5). K7 3 — teks template tetap (konsisten) tetapi tidak dapat dikustomisasi. K8 4 — Sehatly sudah punya driver WA `fonnte` (`PemilihPengirimOtp.php:20`). **Bukan alur penuh** (tidak mencakup registrasi); tidak boleh menjadi pemenang flow.

**Telegram** (`telegram.md`): K1 N/V — UI tidak teramati. K2 4 — `resendCode` + `next_type`/`timeout` (S1). K3 4 — kode batal bila diteruskan/di-screenshot; flood limit; konfirmasi sesi Yes/No (S1). K4 N/V. K5 1 — bukan konteks Indonesia. K6 4 — invalidation + session confirm. K7 3 — level API, kompleks. K8 2 — integrasi baru. Bobot 65% <70% → gagal ambang pemenang.

**Passkeys** (`passkeys.md`): K1 **5** — login = 1 aksi biometrik, tanpa kode (S1/S5). K2 4 — phishing-resistant, public key saja, transparan (S1). K3 3 — pemulihan kompleks: passkey baru bisa 7 hari, pemulihan via SMS/passcode, sinkron per ekosistem (S4/S5). K4 N/V. K5 N/V — dukungan OS Android 9+/iOS 16+; penetrasi Indonesia tidak diukur (tidak ada bukti → N/V, bukan angka karangan). K6 4 — private key tidak dibagikan; pemulihan tetap bersandar SMS. K7 3 — konsep tersembunyi; beda perilaku antar-ekosistem. K8 2 — butuh endpoint challenge WebAuthn + perubahan model sesi; belum ada di stack.

## Yang TIDAK TERVERIFIKASI (membatasi keyakinan)

1. **UI native semua kandidat** (digit, timer, resend, layar error) tidak diamati langsung.
2. **Aksesibilitas N/V untuk semua kandidat** (15% bobot hilang); pedoman di pattern memakai WCAG + `web/AGENTS.md`.
3. SATUSEHAT Mobile: isi FAQ tidak dapat dibaca.
4. Telegram: UI tidak teramati (level API).
5. Passkeys: cakupan perangkat Indonesia tidak diukur.
6. Konsekuensi "kode login dibakar pada percobaan ke-6" belum diuji UX-nya; hanya fakta kode + tes.

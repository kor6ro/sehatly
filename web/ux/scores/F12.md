# Skor F12 — Batal, jadwal ulang, refund

Tanggal riset: **2026-10-02**. Rubrik: `web/ux/rubric.md`. Bukti per aplikasi: `web/ux/evidence/F12/*.md`.
Aturan: nilai hanya bila ada bukti; tanpa bukti = **N/V** (dikeluarkan, bobot dinormalisasi ulang). Pemenang wajib **≥2 sumber independen** dan **≥70% bobot terverifikasi**. Aplikasi dengan red flag tidak boleh dijadikan pola untuk ditiru meski skornya tinggi.

**Titik awal hitungan bersama:** pasien sudah login, punya **satu janji temu berbayar**, dan ingin **(A) membatalkan**, **(B) menjadwalkan ulang**, atau **(C) mengurus refund**. Hitungan diambil dari langkah terdokumentasi (help center/FAQ), **bukan** pengamatan langsung — aplikasi native tidak dipasang (BENCHMARK_PROMPT aturan #4).

**Sumber pola (bukan kandidat yang dinilai):** `sehatly-fase0.md` (baseline kode, satu sumber). Doctolib **berstatus red flag** (warisan F11) → diskualifikasi sebagai pola utuh.

## Alasan per sel (satu fakta berbasis bukti; rujukan = file evidence)

**Halodoc** (`halodoc.md`): K1 **N/V** — tidak ada langkah UI batal/reschedule/refund yang terdokumentasi. K2 3 — jendela 24 jam + janji waktu refund per metode tampil di profil dokter **sebelum booking**, tetapi dua profil menampilkan jendela berbeda dan satu menampilkan “Bayar di rumah sakit” bersamaan dengan kebijakan refund [S1, S2]. K3 N/V. K4 N/V. K5 4 — produk Indonesia, Bahasa Indonesia, metode bayar lokal (VA, GoPay, Halodoc Wallet, AstraPay, kartu) [S3, S4]. K6 3 — tujuan refund per metode dinyatakan (VA → Saldo, e-wallet, kartu); tidak ada bukti masking/consent di alur F12. K7 3 — blok kebijakan konsisten formatnya, tetapi isinya tidak konsisten antar profil [S1, S2]. K8 3 — menampilkan kebijakan + status refund bisa dibangun, backend refund belum ada.

**Traveloka** (`traveloka.md`): K1 3 — reschedule 6 langkah (wajar untuk transaksi berbayar) + refund 2 langkah; tidak ada langkah mubazir yang terlihat [S1, S2]. K2 3 — selisih harga dan estimasi refund dinyatakan, status dapat dilacak, tetapi **biaya & estimasi baru muncul saat pengajuan**, dan dua durasi berbeda muncul di halaman yang sama (5 hari vs 90 hari) [S2]. K3 4 — kegagalan bayar reschedule **tidak menghilangkan tiket lama** (“original flight will not be changed until you have completed the payment”), ada status refund, ada eskalasi non-refundable [S1, S2]. K4 N/V — tidak ada bukti aksesibilitas. K5 3 — perusahaan Indonesia, IDR, TPayLater/VA; halaman yang dibaca berbahasa Inggris [S1–S3]. K6 3 — refund ke metode asal/rekening terdaftar; tidak membahas data sensitif [S2]. K7 3 — banyak kebijakan paralel per produk; dua bagian Q&A serupa di satu halaman [S2]. K8 3 — wizard + linimasa status bisa dibangun; mesin kebijakan/biaya berat.

**Grab** (`grab.md`): K1 4 — batal 2 ketukan (biaya tampil di tombol “PAY TO CANCEL”), sengketa 4 langkah [S3]. K2 **5** — jendela eksplisit per layanan; biaya dikomunikasikan **saat booking** (info card) dan **di tombol konfirmasi**; syarat bebas biaya (pengemudi terlambat/tidak datang) dinyatakan; 100% biaya ke pengemudi; e-receipt terpisah [S1–S3]. K3 4 — jalur sengketa dengan verifikasi GPS/timestamp + refund biaya; namun waktu refund dana perjalanan tidak dinyatakan [S1, S3]. K4 N/V. K5 4 — syarat Indonesia + Help Centre Bahasa Indonesia + pembayaran OVO/tunai [S1, S4]. K6 3 — dana ditahan (pre-auth) lalu dipotong; e-receipt; tidak ada pengelolaan data sensitif. K7 4 — struktur kebijakan/FAQ jelas dan konsisten lintas halaman [S1–S3]. K8 4 — dialog konfirmasi berbiaya + form sengketa dapat dibangun dari kit yang ada.

**NHS App** (`nhs-app.md`): K1 3 — reschedule RS 7 langkah dengan status “pending”; batal RS 6 langkah; batal GP 3 langkah; **reschedule GP harus batal + pesan baru** [S1, S2]. K2 4 — akibat ireversibel (“may remove you from the waiting list”) dinyatakan **sebelum** konfirmasi; hasil review transparan (pending → diterima/ditolak); alasan terstruktur [S1]. K3 3 — penolakan review **tidak menghilangkan** janji lama (“stays as booked”); tetapi pembatalan terlalu dekat waktunya keluar dari app → telepon faskes (pemulihan manual) [S2]. K4 **5** — pernyataan aksesibilitas v10.1: diuji WCAG 2.2 AA Okt 2025 oleh penguji eksternal atas 35 layar, dengan daftar isu yang jujur [S4]. K5 1 — konteks NHS UK, bahasa Inggris, tanpa pembayaran [S1–S5]. K6 3 — alasan berbentuk pilihan (bukan teks bebas), hasil review transparan; tidak ada kontrol privasi F12 spesifik [S1]. **Pemenang tunggal F12 (per aturan rubrik): NHS App — skor 3,40; 100% bobot terverifikasi; ≥2 sumber independen.**
Catatan kejujuran:
- **Grab skor tertinggi (3,83) tetapi tidak boleh menang** — hanya satu penerbit (persis posisi Google Calendar di F11). Mekanismenya tetap dipakai per langkah.
- **Tidak ada kandidat yang mendokumentasikan seluruh rantai batal → jadwal ulang → refund** (NHS tanpa uang; Grab/Traveloka tanpa janji dokter; Doctolib red flag). Karena itu F12 disintesis sebagai **best-of per langkah**, bukan menyalin satu aplikasi.
- **Halodoc gagal ambang 70%** tetapi tetap sumber pola lokal terkuat untuk jendela 24 jam, refund per metode, dan bahasa.
- **Doctolib didiskualifikasi** (red flag privasi F11) — mekanismenya hanya dicatat sebagai pembanding; **bukan** sumber pola terpilih.

## Yang TIDAK TERVERIFIKASI (membatasi keyakinan)

1. **Seluruh UI native kandidat** (Halodoc, Grab, Doctolib, Traveloka, Booking.com, NHS App) — layar/ketukan adalah turunan dokumentasi, bukan pengamatan. Tidak ada akun dibuat, tidak ada form dikirim.
2. **K4 aksesibilitas N/V untuk 5 dari 6 kandidat** (15% bobot hilang); hanya NHS App punya pernyataan terukur.
3. **Refund Booking.com**: waktu proses tidak ada di sumber resmi yang dibuka; angka “3–5 hari” dari PDF pihak ketiga **tidak dipakai**.
4. **Doctolib**: biaya/no-show (S4 hanya indeks), refund (tidak ada di platform), visual UI.
5. **Grab**: Help Centre ID butuh JavaScript (S5) — artikel “Saya dikenakan biaya pembatalan” tidak dibuka; angka biaya ID tidak ada di sumber yang dibaca (PH/SG dipakai sebagai mekanisme, bukan angka).
6. **Halodoc**: UI batal, reschedule (tidak ada bukti), dan apakah ada biaya admin — tidak terdokumentasi.
7. **NHS App**: alasan batal sebagai kode vs teks; angka batas pembatalan (ditetapkan faskes); lama review.
8. **Independensi**: lima dari enam kandidat hanya punya bukti dari **satu penerbit** → tidak ada yang boleh menang selain NHS App; ini membatasi klaim “terbaik” pada level mekanisme, bukan aplikasi.
9. **Hitungan end-to-end nyata** (jumlah layar + ketukan setelah login) tidak dapat diverifikasi untuk kandidat mana pun.

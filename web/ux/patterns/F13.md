# F13 Dashboard dokter (jadwal, antrean, catatan, tulis resep)

Status: draf   |   Tanggal riset: 2026-10-01   |   Keyakinan: **sedang**
(bukti dari dokumen publik/help resmi; skrin aplikasi acuan di balik login tidak terlihat — lihat `web/ux/scores/F13.md` bagian TIDAK TERVERIFIKASI. Pemenang skor keseluruhan Doxy.me (4,05) tapi tanpa alur resep → pattern memakai **pemenang per langkah**.)

## 1. Tujuan pengguna dan metrik sukses

- Peran utama: **dokter** (spesialis), memakai dasbor **di sela pasien** — dominan 390 px (HP) + 1280 px (desktop klinik).
- Tujuan: dari dasbor, dokter melihat **jadwal + antrean hari ini**, **menerima konsultasi berikutnya**, lalu **menulis catatan dan resep** tanpa berpindah aplikasi.
- Metrik terukur:
  - **≤ 2 ketukan** dari strip "Menunggu diterima" di dasbor sampai konsultasi berstatus `berlangsung` (buka dasbor → ketuk Terima → status berubah; AC-2).
  - **≤ 3 ketukan** dari konsultasi `berlangsung` sampai layar tulis resep terbuka (Buka konsultasi → Tulis resep; AC-3).
  - Dasbor terisi dengan **≤ 3 request paralel** (booking, notifikasi, jadwal) dan **1 layar** memuat ketiganya (AC-1).
  - **0 elemen** teks medis (keluhan, obat) terpotong ellipsis di kedua viewport (AC-3/AC-5).
  - Semua kontrol utama **≥ 44 px**; kontras teks ≥ 4,5:1; axe 0 pelanggaran (AC-4).
  - Race dua perangkat (422) pulih dengan **1 refetch**, tanpa kehilangan daftar (AC-6).

## 3. Yang sengaja TIDAK ditiru

- **SimplePractice seluruhnya sebagai sumber pola** — red flag notification overload (bunyi join/leave "no way to turn this sound off"; alert email ePrescribe "required and can't be disabled" — `evidence/F13/simplepractice.md` S1/S4). Hitungan langkahnya tetap dicatat sebagai fakta pembanding, tidak menyalin satu pun polanya.
- **Upsell tier Doxy.me** (Custom Waiting Room/Virtual Background/Captions berbayar) — Sehatly tanpa tier; tidak ada CTA "Jelajahi paket" di dasbor dokter.
- **Foto check-in pasien Doxy.me** — intrusif dan tidak perlu di Sehatly (aturan privasi F13 §9).
- **Doctolib: kunci komputer/akun sama** ("started and ended by the same account on the same computer") — Sehatly **mengizinkan dua perangkat** dengan guard status server (422 + refetch), bukan larangan. **Klik kanan** sebagai jalur utama juga tidak diadopsi (desktop-only, tak tersedia di 390 px) → aksi selalu terlihat sebagai tombol.
- **Practo Ray: cross-sell 4 produk di nav** (Profiles/Feedback/Reach/Consult), **iOS offline read-only** (asimetri platform), dan seluruh aspek aksesibilitasnya (audit 2025: isu kritis di 7/9 layar iOS — `evidence/F13/practo-ray.md` S8) — nav Sehatly tetap bersih; aksesibilitas malah jadi syarat wajib.
- **Jane: e-prescribing via fax/template** (bukan e-resep sungguhan) dan **tanpa bulk sign** — Sehatly sudah punya `POST /konsultasi/{id}/resep`; final tetap per-dokumen (final ≠ massal) sesuai backend `PUT /rekam-medis/{id}/final`.
- **NN/g: jangan dasbor = alat eksplorasi**; hindari pie/donut/gauge untuk angka kuantitatif; jangan tabel padat tanpa header lengket.
- Semua nama merek, ikon khas, ilustrasi, dan teks asli tidak disalin; hanya pola interaksi.

     - `GET /notifikasi?page=1&per_page=10&unread=true` → filter klien baris dengan `payload.konsultasi_id != null`, unik, **maks 5 id** → `GET /konsultasi/{id}` per id (bounded N+1) → `data.konsultasi:{id, status, tipe, mulai_at, pasien:{nama_lengkap}, booking:{...}}` (`KonsultasiAccess::muatan` eager-load `pasien.user, dokter.user, booking`).

Mutasi: `terimaKonsultasiMutation(id)` (**sudah ada**, `lib/api/konsultasi.ts:336`, belum terpakai).
  3. **Buka konsultasi**: navigasi SPA `/konsultasi/{id}` (layar F08: chat Reverb `konsultasi.{id}`, `SoapForm` → `PUT /konsultasi/{id}/selesai` dengan field `catatan_subjektif/objektif/asessment/plan, diagnosis_kerja, saran_tindak_lanjut`).
  4. **Catatan medis**: tombol di layar konsultasi → `POST /konsultasi/{id}/rekam-medis` (`keluhan_utama…plan, diagnosis_kerja, instruksi_tindak_lanjut, status_tindak_lanjut, jadwal_kontrol, tanggal_periksa`) → 201 draft (`status_dokumen='draft'`, `versi=1`) → navigasi `/rekam-medis/{id}` (form edit/final **sudah ada**).   5. **Tulis resep**: `/konsultasi/{id}/resep` (komposer F09 sudah ada): `GET /obat?search=&page=` → `data.obat[] {id, nama_generik, nama_brand, bentuk_sediaan, kekuatan, requires_resep, aturan_pakai_umum, kontraindikasi, harga_jual}`; `POST /konsultasi/{id}/resep` `{catatan_dodio?, items:[{obat_id|nama_obat, kekuatan?, aturan_pakai*, jumlah*, satuan?, is_racikan?, racikan_nama?}]}` → 201 `{resep, warning, warning_grup, acknowledgement}`; 422 `errors.catatan_dodio` bila `tingkat=kontraindikasi` tanpa catatan → field catatan wajib muncul inline.
  6. **Setelah resep**: `data.resep.id` → tautan `/resep/{id}` (`GET /resep/{id}` boleh untuk penulis). **`GET /resep` (antrean) = `tipe:apoteker` saja → dokter TIDAK bisa memakainya** dan **tidak ada endpoint daftar resep untuk dokter** (gap → §12).
  7. **Surat keterangan**: `POST /konsultasi/{id}/surat-keterangan` `{tipe* ∈ surat_sakit|surat_sehat|surat_rujukan|surat_kematian, tanggal_mulai?, tanggal_selesai?, isi?, faskes_tujuan_id?, diagnosis_kerja?, icd10_kode?, alasan_rujukan?, berlaku_sampai?, nomor_sep?}` → 201 `{surat_keterangan, rujukan}`; nomor surat tampil **inline di layar**, bukan di toast. **Belum ada fungsi API di SPA** → buat `buatSuratKeteranganMutation` baru.

## 7. Edge case medis dan bisnis

1. **Pasien tidak hadir (no_show)**: `booking.status` ENUM memuat `no_show`, tetapi **tidak ada endpoint apa pun yang menulisnya** (hanya `menunggu_pembayaran→terjadwal` via pembayaran, `→dibatalkan`, `→kadaluarsa`) → dasbor **menampilkan** status apa adanya, **tanpa** tombol "Tandai tidak hadir". Jangan mengarang aksi; laporkan sebagai gap (§12 butir 5).
2. **Dua perangkat (dokter)**: Terima di HP → desktop stale masih menawarkan Terima → klik → **422 `errors.status`** → alert inline + refetch (state machine `menunggu_dokter→berlangsung` menulis `mulai_at` hanya sekali; guard `FOR UPDATE` di server). Tidak ada data hilang; daftar disegarkan (AC-6). Sama untuk `selesai` (422 ganda `errors.status` + `errors.mulai_at` bila belum pernah dimulai).
3. **STR kadaluarsa**: `dokter.str_berlaku_sampai` **tidak dipublikasikan** ke `GET /me` → dasbor **tidak bisa** memperingatkan; server menyembunyikan slot/booking baru saat STR lewat (guard di pembuatan booking/slot). Konsekuensi UX: antrean mendadak kosong **tanpa kesalahan UI** — copy kosong tidak boleh menyalahkan dokter ("Belum ada booking pada …", bukan "Jadwal Anda bermasalah"). Jangan menampilkan tanggal STR (tidak ada datanya) → §12 butir 6.
4. **Override kontraindikasi**: item resep dengan `warning_grup` tingkat `kontraindikasi` → server minta `catatan_dodio` (422). Komposer menampilkan panel peringatan **sebelum** item + field catatan wajib yang tidak bisa ditutup; catatan tampil sebagai `catatan_dokter` pada layar pasien (aturan F09). Peringatan **tidak pernah memblokir tampilan** item.
5. **Offline**: banner + semua tombol tulis nonaktif (Terima, Simpan catatan, Simpan resep, Surat); draf form mempertahankan isinya; **tanpa antrean mutasi** (keputusan `_global.md` §7) — jangan menjanjikan "terkirim otomatis".
6. **Sesi habis**: refresh single-flight → redirect login → kembali ke dasbor; query state (filter chip di URL) dipertahankan agar kembali ke konteks yang sama.
7. **Order-status advance absen**: `PesananObatService::ubahStatus()` tidak dirutekan → dokter **tidak** melihat/memajukan status pesanan obat; setelah resep dibuat cukup tautan `/resep/{id}` (status `aktif`). Jangan ada band "Proses pesanan" (mustahil).
8. **Booking ≠ konsultasi**: `booking.status` tidak pernah disinkronkan oleh siklus konsultasi (booking tetap `terjadwal` setelah konsultasi selesai) → **dua badge dipisahkan**: badge baris = status booking; badge strip/header = status konsultasi. Jangan menyatukannya atau menampilkan "Selesai" di baris booking karena konsultasi selesai.
9. **Discovery rapuh**: pasien membuat konsultasi tetapi **belum mengirim pesan** → notifikasi (dan strip) belum ada → konsultasi `menunggu_dokter` tak terlihat di dasbor. Copy tidak boleh "Tidak ada konsultasi" secara absolut; tidak ada endpoint cadangan (§12 butir 1).
10. **Aksi massal destruktif dilarang**: batal booking hanya per baris dengan `Dialog` konfirmasi + `alasan_pembatalan` (guard server `STATUS_TIDAK_BISA_DIBATALKAN`); tidak ada "batalkan semua" (konteks medis: pembatalan = keputusan per pasien).

## 8. Aksesibilitas

- **Keyboard-first (kriteria 5)**: chord `g d` (dasbor), `g a` (fokus antrean), `g k` (fokus strip menunggu), `?` → `Dialog` berisi **daftar semua shortcut** (syarat Material: halaman daftar + ≥2 tombol), `Esc` menutup dan fokus kembali ke pemicu (focus trap Radix). Di dalam daftar: `ArrowUp/ArrowDown` memindahkan fokus baris (indikator `--ring`), `Enter` membuka, `a` = Terima (hanya saat fokus di daftar, **mati saat fokus di input/textarea**). Tanpa `ui/command` → `keydown` listener biasa pada root, di-cleanup saat unmount.
- **Urutan fokus**: header (judul → `?` → Muat ulang) → strip menunggu (Terima → Buka) → chip filter → toggle kepadatan → baris antrean → pagination → jadwal.
- **Target sentuh ≥ 44 px** (`h-11`) untuk Terima, Buka, chip, toggle, tombol pagination (Standar: WCAG 2.5.8 hanya 24×24 px; kebijakan Sehatly 44 px — `evidence/F13/standards-a11y.md`).
- **Kontras ≥ 4,5:1** (WCAG 1.4.3): teks utama `--foreground`/`--muted-foreground` di atas `--card`/`--background`; status selalu **teks + ikon + warna** (jangan warna saja — warna tunggu Doxy hanya pelengkap, teks "Menunggu 12 menit" tetap ada).
- **Screen reader**: strip = `<section aria-label="Konsultasi menunggu diterima">`; perubahan status via `role="status"` + `aria-live="polite"` ("Konsultasi diterima"); baris daftar `role="list"`/`role="listitem"`; badge status ikut terbaca karena berisi teks; ikon `aria-hidden`.
- **Teks besar / zoom 200%**: tanpa tinggi tetap pada baris (padding, bukan height), keluhan wrap penuh; data medis **tanpa** `truncate`/`line-clamp`.
- Jalankan `expectNoA11yViolations` (`web/tests/e2e/a11y.ts`) di setiap AC yang menyentuh layar; tetap uji keyboard/SR manual (axe = subset WCAG).

## 9. Privasi

- **Tidak boleh muncul di** toast, `document.title`, URL, atau notifikasi push: nama pasien, keluhan, nama obat, dosis, nomor surat. Judul tab = **"Dasbor Dokter"** / "Konsultasi #<id>" (id numerik di URL diperbolehkan, pola F08).
- URL dasbor hanya berisi **filter non-medis**: `?tanggal=2026-10-01&status=terjadwal` — jangan menaruh nama/keluhan di query (bocor lewat history/share).
- **Dokter hanya melihat pasien miliknya**: server `ownDokterOrFail` (403) + `KonsultasiAccess::untukDokter`/`findForRead` (404 untuk baris orang lain) — UI mempercayai 403/404, merender `ForbiddenState`/`NotFoundState` tanpa membocorkan isi.
- **NIK termasking** di `BookingResource` (`NikMasker::mask`) — tampilkan bila perlu, jangan pernah dipakai sebagai label utama.
- Notifikasi server sudah generik ("Pesan baru.", "Ada pesan baru di konsultasi Anda.") tanpa nama/keluhan — **pertahankan**; jangan menambah payload medis ke `notifikasi.payload` (UU PDP, pola F02).
- Screen recording/ruang publik: toast generik membuat dokter aman membuka dasbor di layar bersama.

**Koreksi implementasi F13 (2026-10-02, dicatat saat membangun `web/tests/e2e/dokter-f13.spec.ts`):**

11. **AC-1: himpunan request berubah mengikuti keputusan #1.** Teks AC-1 masih menyebut `GET /notifikasi?unread=true` sebagai sumber strip. Karena #1 memilih `GET /konsultasi` (supaya konsultasi tanpa pesan tetap terlihat), implementasi memuat **tiga** permintaan data: `GET /dokter/booking?tanggal=<hari-ini>`, `GET /konsultasi?page=1&per_page=100`, dan `GET /dokter/{id}/jadwal`. `/me` dipakai bersama shell dan tidak dihitung. Strip sekarang = baris `menunggu_dokter` dari `GET /konsultasi`; "Buka konsultasi" pada baris booking di-resolve dari `booking.id` pada daftar konsultasi (booking tanpa konsultasi tidak menampilkan tautan — tidak ada id yang dikarang).
12. **AC-9: klausa `body.innerText` dilingkupi ke halaman resep.** Baris antrean memang menampilkan `pasien.nama_lengkap` (syarat §5), jadi nama pasien *sah* ada di DOM dasbor. Uji privasi karena itu memeriksa (a) toast/title/URL sealur terima, dan (b) `body.innerText` **di halaman komposer resep** tidak memuat nama pasien — di sana nama itu tidak punya alasan untuk ada. Judul, URL, dan toast tetap dicek bebas dari nama pasien/keluhan/obat.
13. **Chip tanggal dan toggle kepadatan memakai `<Button aria-pressed>` (bukan `ToggleGroup type="single"`).** Radix `ToggleGroup` mode `single` merender `role="radio"` + `aria-checked` dan secara eksplisit tidak merender `aria-pressed` (diverifikasi di paket terpasang), sedangkan §11 mensyaratkan `aria-pressed=true` pada chip "Hari ini". Semantik satu-pilihan tetap terjaga (satu tombol aktif), target ≥44 px, dan `role="group"` dengan `aria-label` membungkus keduanya.
14. **Perbaikan a11y pada `obat-autocomplete.tsx` (F09).** Axe menemukan `nested-interactive`: `<li role="option">` membungkus `<button>`. Struktur diubah menjadi `ul[role=listbox] > li[role=presentation] > button[role=option][aria-selected=false]`, dan keadaan kosong dirender sebagai `<p>` di luar listbox. Tidak ada perubahan perilaku/API; ini menutup pelanggaran axe pada AC-3.
15. **Kontras `text-success` pada `resep-composer.tsx`.** Baris "Resep … tersimpan" memakai `text-success` (≈3,6:1 di atas putih) dan gagal axe `color-contrast` saat AC-9; sekarang teks memakai warna default dengan ikon `CircleCheck` berwarna `--success` — status tetap teks + ikon + warna, tanpa warna sebagai satu-satunya kanal.

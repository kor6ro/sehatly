# F05 Pilih jadwal dan booking

Status: draf   |   Tanggal riset: 2026-10-01   |   Keyakinan: sedang

Skor & pemenang per langkah: `web/ux/scores/F05.md`. Bukti per aplikasi: `web/ux/evidence/F05/*.md`. Semua klaim aplikasi lain di file ini membawa sumber + tanggal akses **2026-10-01**.

## 1. Tujuan pengguna dan metrik sukses

- **Peran:** Pasien (sudah login; tanpa login tidak ada `POST /booking`). Dokter & admin klinik hanya membaca (`GET /dokter/booking`) — di luar flow ini.
- **Tujuan:** Satu pasien memesan **satu slot** dengan satu dokter, **tahu biaya, durasi, dan status** sebelum menekan kirim, lalu melihat booking masuk daftar dan statusnya.
- **Metrik (terukur):**
  - **M1:** ≤ 3 layar dari daftar dokter sampai konfirmasi booking (daftar `/dokter` → profil → halaman booking dengan kartu sukses).
  - **M2:** Setelah halaman booking terbuka, tombol "Kirim booking" aktif dalam **≤ 4 ketukan** (tanggal ×1, jam ×1, sisanya default/form opsional).
  - **M3:** Tidak ada ketukan sia-sia: mengganti tanggal **tidak** memaksa ulang input keluhan/lampiran (dipertahankan).
  - **M4:** 0 booking optimis: setiap baris di "Booking terakhir" berasal dari `GET /pasien/booking` setelah sukses.

- **Zocdoc:** pertanyaan survei "How did you hear about us?" + promosi "Enable Autofill" + prompt asuransi **sebelum konfirmasi** (rekaman Z11/Z12, versi Desember 2024; diakses 2026-10-01) — kebisingan sebelum tugas inti selesai tidak diadopsi.
- **Practo:** lencana **Prime**/Practo One berdampingan dengan CTA dan framing "No assurance that you will meet the doctor you booked" untuk tier non-Prime (P6/P8, 2026-10-01) — Sehatly tidak punya tier berbayar yang menekan aksi utama; consent pemasaran default-in (P11) tidak diadopsi; denda ₹50 & auto no-show 72 jam (P13) **tidak** diadopsi tanpa keputusan pemilik produk.
- **Halodoc:** consent menyatu sebagai teks pasif di bawah dialog login (R1, 2026-10-01) — tidak diadopsi sebagai model consent; kontradiksi biaya "Bayar di rumah sakit" (H1) vs "selesaikan pembayaran" (H2) — Sehatly memakai **satu** sumber biaya (`dokter.biaya_konsultasi_online`) yang ditampilkan konsisten di ringkasan dan atas tombol kirim.
- **Alodokter:** halaman web yang hanya berisi funnel unduh aplikasi (A3, 2026-10-01) — aksi utama tidak boleh ditutupi ajakan unduh/pesan lain.
- **Umum:** tidak menyalin ilustrasi, ikon khas, layout unik, nama merek, atau teks UI pihak ketiga. Semua copy di bawah adalah milik Sehatly (Bahasa Indonesia).

## 7. Edge case medis dan bisnis

1. **Slot diambil saat konfirmasi (dua pasien sama-sama kirim):** server menjawab **422 field `slot`** (`Slot sudah penuh untuk waktu ini.` / `Slot sudah lewat.` / `Slot tidak dipublikasikan oleh jadwal dokter.` / `Slot tidak tersedia pada tanggal tersebut.`). Tampil `SlotTakenNotice` **di atas form, bukan toast**; form tidak direset; pasien memilih slot lain dalam 1 ketukan; baris optimis **tidak pernah** ditampilkan.
2. **Dokter batal / sistem batalkan:** status `dibatalkan` + `BookingStatusNote`: "Slot ini sudah dilepas dan dapat dipesan kembali." + `dibatalkan_oleh` ("dibatalkan oleh dokter: …"). Bedakan dari `no_show` ("Booking ditandai tidak hadir. Tidak ada pembatalan yang dicatat.") dan `kadaluarsa` — ketiganya memakai teks + ikon + warna (`BookingStatusBadge`), bukan warna saja.
3. **Zona waktu WIB/WITA/WIT:** jadwal dokter adalah jam dinding **Asia/Jakarta** di server. Slot **ditampilkan** dalam zona waktu pengguna dengan **label zona wajib** (`09.00–09.15 WIB`), format jam `id-ID` (`09.00`), dan ringkasan pesanan ikut melabeli zona. Bila zona perangkat ≠ Asia/Jakarta, ringkasan menampilkan **kedua** zona (`10.00 WITA (09.00 WIB)`). Nilai yang dikirim ke `POST /booking` tetap `H:i:s` milik server (konversi hanya tampilan, memakai `Intl`, tanpa offset hardcode). Pasien WITA/WIT melihat jam sudah dikonversi + labelnya, sehingga tidak ada kejutan "jamnya beda". *(Diputuskan & diimplementasikan 2026-10-01; lihat `_global.md` §5 dan `lib/waktu.ts`.)*
4. **Pasien membuka di dua perangkat / dua tab:** tab pertama sukses (201) → kartu sukses + daftar ter-invalidate. Tab kedua yang masih mengirim slot sama menerima **422 `slot`** → notice + ajakan `Muat ulang daftar` (refetch `GET /pasien/booking`). Tidak ada sinkronisasi realtime (Reverb tidak dipakai F05) — kejujuran layar: baris baru muncul setelah refetch, bukan "muncul sendiri".
5. **Kuota, hari libur dokter, STR kedaluwarsa:** semua keputusan server (`slots[]` kosong atau `tersedia:false` + `alasan`) — grid menampilkan alasan, tidak menyembunyikan.
6. **Batas horizon:** kalender hanya membatasi masa lalu (`startMonth` = hari ini), **tanpa batas atas** — kebijakan horizon adalah keputusan pemilik (§12).
7. **Biaya tidak berubah oleh flag:** "Rujukan adalah keterangan asal-usul, bukan potongan harga" (copy sudah ada); ringkasan biaya identik di atas form dan di atas tombol kirim.
8. **Lampiran tanpa endpoint unggah:** form menerima URL yang sudah diunggah pasien — jangan menampilkan `file picker` yang mengaku mengunggah; hint menjelaskan batasan.

## 8. Aksesibilitas

- **Urutan fokus:** header → ringkasan → kalender (DayPicker navigasi keyboard bawaan) → grid jam → field detail → tombol kirim → daftar booking. Tidak ada `tabindex` manual.
- **Label:** setiap input lewat `Field` (label + `hint` + `errors`); checkbox punya `Label htmlFor`; kalender `aria-label="Pilih tanggal kunjungan"`.
- **Grid jam:** `role="listbox"` + `role="option"` + `aria-selected`; slot nonaktif = `disabled` **dan** tetap memuat teks alasan (bukan opacity saja); petunjuk disable ("Pilih jam mulai untuk melanjutkan.") adalah teks, bukan hanya warna tombol.
- **Target sentuh ≥ 44 px:** tombol slot `min-h-11` (44 px) dan tombol kirim `min-h-11`; tombol navigasi kalender `size-11` (44×44); tombol hari kalender `h-11 w-full` (44 px tinggi, selebar kolom grid) — diverifikasi via AC-9 di 390 px.
- **Kontras ≥ 4,5:1:** semua teks dari token (`--foreground`, `--muted-foreground` di atas `--background`/`--card`); status teks + ikon + warna (`BookingStatusBadge`).
- **Fokus terlihat:** `--ring` pada semua elemen interaktif (jangan dihapus `outline`); tombol slot dan tombol kalender memakai `focus-visible:ring-2` eksplisit karena bukan komponen `Button`.
- **Pengumuman pembaca layar:** `SlotTakenNotice` `role="alert"`; banner luring `role="status"`; kartu sukses `role="status"`; perubahan jumlah slot tersedia diumumkan lewat teks "X dari Y jam dapat dipesan" yang selalu terlihat.
- **Teks besar/zoom:** layout memakai aliran (`flex-wrap`) — tidak memotong biaya/jadwal dengan ellipsis (aturan AGENTS untuk data medis/jadwal).

## 9. Privasi

- **Tampil:** nama dokter, spesialisasi, biaya, durasi, tanggal/jam terpilih + zona, status booking, nomor booking (`nomor_booking`), alasan pembatalan bila pasien mengisinya.
- **Disamarkan/tidak tampil:** NIK dan data profil lain tidak disentuh flow ini; `keluhan` **tidak** ditampilkan di toast, **tidak** masuk URL, **tidak** di judul tab, **tidak** di notifikasi (judul tab tetap "Booking dengan {dokter}" tanpa keluhan).
- **URL:** hanya `/booking/:dokterId` + deep link `?tanggal=Y-m-d&jam=H:i:s` (format aman, sudah didukung). **Dilarang** menaruh `keluhan`, nama anggota keluarga, atau URL lampiran di query.
- **Toast/flash:** hanya `message` dari server (konfirmasi generik) — tanpa isi medis.
- **Lampiran:** URL dapat berisi lokasi berkas medis → tampilkan nama berkas, potong URL panjang di layar daftar; jangan menampilkan URL lengkap di kartu sukses.
- **Daftar "Booking terakhir":** tampilkan identitas klinis minimal (dokter, tanggal, status); keluhan tidak ikut di baris ringkas.
- **UU PDP:** consent pemrosesan data kesehatan (F02) **belum ada UI** — ketergantungan ini dicatat di §12; pattern ini tidak mengaku sudah patuh.

## 10. Kriteria penerimaan (terukur)

- [ ] **AC-1:** Di `/booking/:dokterId` dengan tanggal & jam kosong, tombol "Kirim booking" `disabled` dan terlihat teks "Pilih tanggal kunjungan untuk melanjutkan."; setelah tanggal dipilih teks berubah menjadi "Pilih jam mulai untuk melanjutkan."; setelah jam dipilih teks hilang dan tombol aktif (asumsi jaringan normal).
- [ ] **AC-2:** Memilih tanggal berbeda: permintaan `GET /dokter/{id}/slot?tanggal=<baru>` terpicu, blok slot menampilkan skeleton, dan field "Jam mulai terpilih" kembali "Belum ada jam yang dipilih" (slot lama di-reset).
- [ ] **AC-3:** Dengan respons slot yang memuat slot `tersedia:false`, slot tersebut tetap dirender sebagai tombol nonaktif berisi teks `alasan` (bukan hilang), dan footer "X dari Y jam dapat dipesan." benar.
- [ ] **AC-4:** Dua bercabang 404/`slots:[]` dibedakan: (a) 404 dokter → `NotFoundState` "Dokter tidak dapat dipesan" + aksi `Kembali ke direktori`; (b) `slots: []` → `EmptyState` "Tidak ada jam tersedia" + penyebabnya. Masing-masing muncul tanpa retry loop. *(Dikoreksi 2026-10-01: `GET /dokter/{dokter}/slot` terverifikasi terdaftar dan menjawab 200 — 16 slot, `timezone: Asia/Jakarta`; cabang "route absen" beserta input jam manual dihapus. Lihat §12 #1.)*
- [ ] **AC-5:** Submit valid memicu `POST /api/v1/booking` → 201: kartu sukses memuat "Booking <nomor> berhasil dibuat." **dan** baris booking baru ada di "Booking terakhir" setelah refetch (baris tidak muncul sebelum respons server).
- [ ] **AC-6:** `POST /booking` dijawab 422 dengan field `slot`: muncul elemen `[data-slot="slot-taken-notice"]` ber-`role="alert"` berisi "Jam yang dipilih tidak dapat dipesan" + pesan server; nilai keluhan dan baris lampiran **tetap ada** di form.
- [ ] **AC-7:** Tiap blok memiliki tiga state wajib: skeleton saat loading; `EmptyState` dengan aksi ketika kosong; `ErrorState` dengan tombol "Coba lagi" saat 5xx/jaringan (dicek pada blok slot dan daftar booking).
- [ ] **AC-8:** Pita jam dan ringkasan pesanan selalu menampilkan **label zona waktu** (mis. "09.00–09.15 WIB" untuk zona WIB) dan format jam `id-ID` ("09.00", bukan "09:00"). Jam dikonversi ke zona perangkat memakai `Intl`; bila zona perangkat ≠ Asia/Jakarta, ringkasan menampilkan kedua zona ("10.00 WITA (09.00 WIB)"). Nilai yang dikirim tetap `H:i:s` server.
- [ ] **AC-9:** Pada 390 px, seluruh target sentuh utama (tombol slot, chip tanggal, "Kirim booking", tombol kalender) berukuran ≥ 44 px; semua input punya label terlihat; indikator fokus keyboard terlihat pada slot & tombol; status booking memakai teks + ikon + warna.
- [ ] **AC-10:** Offline (`navigator.onLine === false`): banner luring (`role="status"`, `data-testid="offline-banner"`) tampil, tombol kirim dinonaktifkan, **nilai form dipertahankan**; kembali online → banner hilang tanpa reload dan tombol aktif kembali. Tidak ada antrean mutasi (keputusan F15, `_global.md` §7 #1).
- [ ] **AC-11:** Setelah sukses, `page.url()` hanya mengandung `/booking/:dokterId` (+ `?tanggal`/`?jam` bila deep link); teks keluhan tidak ada di URL, `document.title`, atau isi toast; isi toast hanya pesan konfirmasi generik.

## 12. Pertanyaan terbuka

# F09 Resep dan detail obat

Status: draf   |   Tanggal riset: 2026-10-01   |   Keyakinan: **sedang**
(bukti kuat dari dokumen resmi/regulator; skrin aplikasi acuan di balik login tidak terlihat — lihat `web/ux/scores/F09.md` bagian TIDAK TERVERIFIKASI)

## 1. Tujuan pengguna dan metrik sukses

- Peran utama: **pasien** (Android kelas menengah-bawah, termasuk lansia). Turunan: apoteker (verifikasi) dan dokter (sudah punya composer, tidak diubah di sini).
- Tujuan pasien: dari daftar resep, membuka **satu** resep lalu **memahami dosis tiap obat** dan **tahu aksi berikutnya** (tebus/pantau/minta perpanjangan) tanpa bertanya ke siapa pun.
- Metrik terukur:
  - **≤ 2 ketukan** dari `/pasien/resep` sampai nama obat + dosis terlihat (AC-1).
  - **0 elemen** teks medis terpotong ellipsis di 390 px (AC-2).
  - **100%** target sentuh utama ≥ 44 px; kontras teks utama ≥ 4,5:1 (AC-3, AC-4).
  - Pasien dengan resep kedaluwarsa **tidak pernah** menekan tombol checkout yang pasti gagal (AC-5).

## 7. Edge case medis dan bisnis

1. **Resep kedaluwarsa** (`is_kedaluwarsa=true`, aturan 7 hari): badge `Kedaluwarsa` + band aksi "Resep kedaluwarsa — konsultasi ulang"; **tombol checkout tidak dirender** (bukan disabled yang bisa diklik); QR tetap tampil untuk arsip.
2. **Override kontraindikasi dokter** (`catatan_dodio`): pasien melihat **Catatan dokter** lengkap tepat di atas daftar obat — peringatan medis tidak boleh disembunyikan di balik ketukan (rubrik red flag). Tidak ada mekanisme "tutup peringatan" untuk pasien.
3. **Verifikasi ditolak** (`StatusVerifikasiResep='ditolak'`, verifikasi sekali-waktu & terminal oleh apoteker): banner destructive + alasan; pasien tidak bisa checkout; jalan keluar = konsultasi ulang. `ada_koreksi` → tampil sebagai "Ada koreksi" + catatan.
4. **Stok habis / apotek alternatif** (`GET /obat/{id}/stok` = 0): item ditandai "Stok habis"; band aksi turun ke "Sebagian obat belum tersedia". Endpoint pindah-apotek tidak ada → tawarkan "Pilih apotek lain saat pemesanan" hanya bila backend checkout mendukung; jika tidak, jangan menjanjikan (Pertanyaan terbuka #3).
5. **Ambiguitas dosis** (`aturan_pakai` teks bebas, maks 255 char): tampilkan **utuh** (wrap, tanpa ellipsis, tanpa potong); bila melebihi 255 tidak mungkin (validasi), bila membingungkan sediakan aksi "Tanya apoteker" yang menyalin id resep (selaras pola antrean apoteker berbasis id ketik — gap yang sudah tercatat).
6. **Resep anak (dosis per berat badan)**: tidak ada field `berat_badan`/`dosis_per_kg` di endpoint → tampilkan apa adanya dari `aturan_pakai` + `catatan_dokter`; **jangan menebak**. Pertanyaan terbuka #5.
7. **Terapi ganda/duplikat**: tertangani `GET /resep/{id}/cek-interaksi` sumber `riwayat_resep` — tampilkan sebagai peringatan bertingkat; peringatan **tidak pernah memblokir** tampilan (aturan backend), pasien tetap melihat item + catatan.
8. **Resep racikan** (`data-racikan` sudah ada): kartu item khusus, jumlah dalam "bungkus", nama racikan tetap tanpa pemotongan.
9. **Dua perangkat / buka ganda**: idempoten — `POST /resep/{id}/checkout` retry 0; setelah sukses, refetch menampilkan status sebenarnya (guard server).

## 8. Aksesibilitas

- **Urutan fokus**: kembali → band aksi → item → peringatan → catatan dokter → QR/token (QR `role="img"` + `aria-label` sudah ada).
- **Teks medis**: nama obat `text-lg`, aturan pakai `text-base` minimal; **dilarang** `truncate`/`line-clamp` pada data medis (sudah bersih dari itu di kode F09 saat ini — pertahankan); kompatibel WCAG 1.4.12 (line-height ≥1,5×, spasi paragraf ≥2×).
- **Target sentuh ≥ 44 px** (WCAG 2.5.5 44×44 CSS px; Apple HIG 44 pt; Material 48 dp — `bpom-label.md` B7/B12/B13) untuk CTA, filter, baris resep.
- **Kontras ≥ 4,5:1** (WCAG 1.4.3) teks `--foreground`/`--muted-foreground` di atas `--card`/`--background`; status selalu **teks + ikon + warna** (jangan warna saja).
- **Label pembaca layar**: tiap kartu item punya `aria-label` gabungan, mis. "Amoxicillin 500 miligram, kaplet, aturan pakai: 1 tablet setelah makan, 3 kali sehari, jumlah 21 tablet, harga 45.000 rupiah". Band aksi = `role="status"` + `aria-live="polite"` agar perubahan status diumumkan.
- **Fokus terlihat** via `--ring`; teks bisa diperbesar 200% (WCAG 1.4.4) tanpa hilang isi (layout wrap, bukan fixed height).

## 9. Privasi

- Nama obat/dosis/tanggal konsultasi **tidak** muncul di: toast (sonner), judul tab, URL, atau notifikasi. (Aturan AGENTS.md; pola notifikasi-disembunyikan dari Medisafe.)
- Token QR tampil hanya di halaman detail setelah login; jangan taruh token resep di URL (pakai path `/resep/{id}` saja).
- `catatan_dokter` dan catatan apoteker = data kesehatan (UU PDP): hanya pemilik (pasien/dokter/apoteker sesuai RBAC) — mengandalkan guard backend 403 yang sudah ada; UI menampilkan `ForbiddenState` tanpa membocorkan isi.
- Error/hak akses tidak menampilkan isi resep; pesan generik.

## 12. Pertanyaan terbuka

1. **Endpoint antrean apoteker** (`GET /resep?status=…` untuk apoteker): gap sudah tercatat di `flows.md`; tanpa ini, verifikasi tetap berbasis id ketik. Perlu keputusan: tambah endpoint vs tetap manual.
